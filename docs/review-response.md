# MoonPressure 初审意见修订说明

修订日期：2026-10-21。已收到初审未通过通知；本文件说明新增实现和复审证据，不代表已通过复审。

## 接受的问题与新增职责

0.1.0 的净核心确实集中在余量、差分及阈值滞回。它能观测压力，却不能决定多个待运行作业如何共同占用共享预算。本轮在原有任务准入范围中新增 `admission` 包，负责**受层级 CPU/内存约束的整组批次选择，以及带版本检查的预留提交与释放**。不是将原有统计变换重新包装成调度器。

|核心职责|实际实现|超出单项变换的部分|
|---|---|---|
|资源约束建模|admission/topology.mbt|验证父子关系和环，跨分支作业的每条申请向全部祖先收费；保留共同约束，不能先把每个叶子压成独立标量|
|整组批次优化|admission/search.mbt|有界分支定界，联合选择互补 CPU/内存请求，保证协同作业全有或全无；结果依赖请求之间的竞争关系|
|预留事务与生命周期|admission/ledger.mbt|方案绑定账本与版本，整批提交、拒绝过期方案、显式释放；缩额保留已有预留并报告欠额，失败不发生部分预留|
|可解释延后|admission/topology.mbt、report.mbt|按最终所选组合重建每个延后作业的具体祖先资源冲突/压力门禁，而非只有总队列的暂停布尔值|

窗口最多16作业/64节点，价值由调用方指定；不声称算法原创、全局公平调度、无限窗口最优或内核资源保证。多根只代表调用方确认独立的可见层级，隐藏共同祖先不作推断。

## 输入关系如何改变结果

所有数值均为明确的合成输入；内存以演示单位表示，实际 API 单位为字节，CPU 为 millicore。

1. **共享关系**：L、R 各有100内存余量，A、B分别请求60。它们共享预算100的父组时，只能选A；保持叶子测量和申请不变，改为两个独立预算100的父组，选A+B。逐叶调用最小余量会让两个请求各自通过，无法解决共同父组超分配。
2. **组合关系**：CPU和内存各10；A申请(内存10,CPU10)，价值9，B申请(6,4)、C申请(4,6)，价值各6。选择B+C得12，而FIFO或先取单项最高价值的A只得9。仅将C内存改为7，B+C不可行，结果改为A。不是把CPU和内存压成一个总分后排序。
3. **协同与门禁**：G须同时在L、R各获取(4,4)，价值20；独立作业S只在L请求(6,6)，价值1；父组预算(12,12)。R有压力时G整组等待、S可运行；R开放后G整组准入、S受共同父预算阻挡，不出现G只占住L等待R的半组状态。
4. **时序关系**：预算100，两次规划各申请60。第一份提交后版本推进，第二份以 `StalePlan` 失败，余额保持40；缩额至50后已有预留仍为60、欠额10。明确释放第一项后，新方案可以使用50，不能用两次独立的“60≤100”判断重复准入。

## 可复现入口与证据

```sh
moon run examples/admission --target wasm-gc
moon test admission --target wasm-gc --deny-warn
python scripts/verify_admission.py wasm wasm-gc js
```

演示输出6个关系案例和1个生命周期案例；验证器另外读取60个确定性生成输入。Python 独立枚举全部子集、重新沿父链计算资源和门禁、比较价值/数量/ID目标并重建所有延后原因；不调用 MoonBit 搜索实现。本轮 Windows 三后端各30项库/文档测试通过，其中新增准入包12项；每后端66个选择案例与生命周期检查通过。证据见 test-evidence/windows-core-2026-10-21.json、admission-oracle-2026-10-21.json。

新增原生端到端入口 `examples/admission-live` 已完成 native check；直接 Linux 测试机当前连接超时，未将旧0.1.0 Linux记录当成本轮新增原生验证。当前原生运行状态与实际归档消费结果见 release.md；远端 CI 增加了新规划器 oracle 和真实采集衔接步骤。

## 生态与原创范围复核

2026-10-21 阅读 [moonpool 仓库 README](https://github.com/moonbitstack/moonpool)：其公开说明包括资源池、重试、速率/配额及并发门禁；阅读 [moontask 仓库 README](https://github.com/nexacodes/moontask)：其公开说明包括异步队列、Redis 后端、任务租约、重试及队列暂停/恢复。两者均为 Apache-2.0。本轮不重做这些职责；新增范围是 cgroup 可见层级中的多资源整组选择和资源预算预留。这里比较的是公开 README 的能力边界，未据此断言其全部源码都没有类似实现。原有 sysinfo/subproc 比较仍见 ecosystem-supplement-2026-10-18.md。

新增代码为本项目原创 MoonBit 实现，无上述项目源码移植；资源语义依据 [Linux cgroup v2 官方规范](https://docs.kernel.org/admin-guide/cgroup-v2.html)。AI 辅助范围与本人理解要求见 AI_USAGE.md。赛事页面已于2026-10-21复读[官方源码](https://github.com/moonbitlang/Hackathon2026/blob/main/src/App.tsx)，仍标明10月31日截止并允许未通过项目修改；本次未代提交报名表或联系赛事方。
