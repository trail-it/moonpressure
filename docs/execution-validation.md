# 0.3.0 派发闭环、模型与规划成本

2026-10-21 在用户指定的真实 Linux 服务器隔离副本上运行，运行时代码对应 `7d73c154fef0fbeff64cadb02bc20a7e139c09a0`。Linux 7.0.0-38-generic，x86_64，moon 0.1.20261012 / moonc v0.10.15+943464bfa。没有覆盖服务器原有源码或传输凭据。以下证据不覆盖重启恢复、分布式执行、内核资源保证或真实 OOM。

## 实际子进程闭环

`scripts/verify_execution.py` 以真实cgroup观察初始化 MoonBit 协调器，宿主依据其 Start/Stop 动作创建并等待固定演示进程。实际启动5个子进程，最多同时2个，每个触碰1MiB缓冲区、有8秒截止，并核对与协调器处于相同cgroup。

- 整体占满预算的A价值9，两个互补的B/C价值各6，实际启动B+C，A留在队列后被取消。
- 不存在的可执行文件真实启动失败，确认无子进程才释放；重试获得新ticket，旧ticket迟到退出被拒绝，当前预留保留。
- 非零退出码7变为Failed并释放；Running取消先转Stopping，进程仍活着时预留仍在，宿主终止并实际wait后才释放。
- Starting取消在确认未创建进程后释放。所有自有子进程被回收，最终预留为0；未修改cgroup，未向其他进程发送信号。

详见 [脱敏执行摘要](test-evidence/linux-execution-0.3.0.json)。这证明生命周期衔接可运行；申请数值仍是声明值，没有用它冒称真实吞吐量提升或严格资源隔离。

## 独立动态模型

`scripts/verify_dispatch.py` 在同一长生命周期 MoonBit 协调器协议上运行8种子、2,000次事件；独立模型重算活跃作业的全部祖先预留并穷举待选组合，逐步比较状态、余额/欠额、版本与动作。覆盖全部7个状态、启动/退出/取消/重试/遗忘/刷新，以及过期回调、未知作业和非法状态；失败操作必须保持原状态。另有16次畸形或超长协议帧检查。全部通过，见 [模型摘要](test-evidence/dispatch-model-0.3.0.json)。随机模型不是形式证明，五项库测试补充明确的顺序和边界反例。

## 合成工作集对照与实际规划成本

`examples/admission-bench` 产生20个确定性合成工作集，含互补申请、混合门禁/整组申请，以及64节点、16任务的密集边界。独立Python检查可行性，基线为FIFO逐个尝试（跳过放不下者）和按声明价值降序逐个尝试。比较的是所选组合的**声明价值**，不比较Python与MoonBit运行速度，不代表吞吐收益。

精确规划对FIFO有17组严格更高，对价值贪心有13组严格更高，其余持平。互补案例为48对42/36。每个案例预热后执行3次原生规划，使用单调时钟；本机单次样本不是性能承诺。

|案例|FIFO价值|价值贪心|精确价值|规划中位数|探索节点|
|---|---:|---:|---:|---:|---:|
|互补16任务|42|36|48|63微秒|3,600|
|全部可行16任务|16|16|16|4微秒|33|
|64层16任务密集竞争|8|8|8|39,918微秒|60,059|

其余混合案例中位数5～355微秒。密集竞争约40毫秒，说明有界精确选择仍有成本，不能宣称全部场景快于贪心；最多16任务的窗口限制是接口契约。完整输入和每组结果由脚本生成，脱敏表格见 [对照摘要](test-evidence/linux-benchmark-0.3.0.json)。
